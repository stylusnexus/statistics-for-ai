Random Variables: Expectation, Variance & the Rules for Combining Them

Token counts, latencies, and right-or-wrong scores are all numbers that change from run to run. This lesson gives you the two summaries that matter for any such number, and the rules for what happens when you scale, add, or average them.

In Lesson 2 you summarized a pile of numbers you already had. In Lessons 3 and 4 you assigned probabilities to outcomes you hadn't seen yet. Now you join the two: attach a number to each uncertain outcome, and ask what that number does on average and how much it wobbles. Once you can do that, questions like "what does a request cost us?", "how long does the whole agent take?", and "how noisy is this eval score?" become short calculations instead of guesses.

1. A random variable is a number attached to an outcome

An outcome by itself ("the model produced this particular response") isn't a number. A random variable is a rule that turns each outcome into one. You pick the rule based on what you want to know about the response:

X = tokens in the response

Whatever text the model writes, X counts its tokens. Takes whole-number values. A discrete variable.

C = 1 if the answer is correct, else 0

The Bernoulli variable from Lesson 4. One response in, a 0 or 1 out.

T = seconds until the response arrives

Can be any value on a continuous scale, so it is a continuous variable. Lesson 13 handles those; this lesson stays with discrete ones.

The word "random" only means the value isn't known until the outcome happens. Before the request runs, X is uncertain. After it runs, you have one observed value, an ordinary number from Lesson 2. The distribution is the rule that tells you, in advance, how likely each value is.

2. The PMF and the CDF

For a discrete variable, the probability mass function (PMF) lists each possible value and its probability. The probabilities must sum to 1, the same requirement as in Lesson 3. Say a team logs a month of traffic on a support assistant and groups response lengths into four sizes:

Response sizeX (tokens)P(X = x)P(X ≤ x)
Short answer1000.40.4
Normal answer2000.30.7
Long answer4000.20.9
Very long answer8000.11.0
0.4 + 0.3 + 0.2 + 0.1 = 1.0

The last column is the cumulative distribution function (CDF): F(x) = P(X ≤ x), the running total of the PMF. It answers "what fraction of responses are at most this long?" For example, F(400) = 0.4 + 0.3 + 0.2 = 0.9, so 90% of responses are 400 tokens or fewer. Flip it around and you get tail questions for free: P(X > 400) = 1 − F(400) = 0.1, the share of responses that run very long. Percentiles from Lesson 2, like p90, are just the CDF read backward.

Key Insight The PMF tells you how likely each exact value is. The CDF tells you how likely a value is to be at most some threshold. Latency budgets, max-token limits, and context-window limits are all threshold questions, so the CDF is usually the one you use in practice.

3. Expected value: the probability-weighted average

The expected value E[X] is each possible value multiplied by its probability, then summed. It is the mean of the distribution, the number the long-run average of observed values settles toward.

E[X] = 100(0.4) + 200(0.3) + 400(0.2) + 800(0.1)
= 40 + 60 + 80 + 80
= 260 tokens

Note that 260 is not one of the four possible sizes. No single response is 260 tokens long. Expected value is a balance point, not a prediction of the next draw. The chart below shows it: the long right tail (the 800-token bar, only 10% of traffic) pulls the balance point well above the most common size.

PMF of response length. Dashed line: the mean, 260 tokens. Shaded band: one standard deviation (about 211) either side of the mean, from the calculation in section 4.

Worked example: expected cost per request

A team prices a request in micro-dollars (µ$): a fixed 400 µ$ for processing the prompt, plus 2 µ$ for every output token. These prices are illustrative. The cost of a request is itself a random variable, Y = 2X + 400. To find E[Y] you could compute the cost of each size and weight it:

Cost of each size: 100 → 600, 200 → 800, 400 → 1,200, 800 → 2,000
E[Y] = 600(0.4) + 800(0.3) + 1,200(0.2) + 2,000(0.1)
= 240 + 240 + 240 + 200
= 920 µ$

The linearity rule in section 5 gets the same answer without the table: 2(260) + 400 = 920. At 1,000,000 requests a month, the expected bill is 920,000,000 µ$, which is $920. Expected value is how you turn a per-request distribution into a budget.

4. Variance and standard deviation of a random variable

Lesson 2 defined variance as the average squared distance from the mean, computed over a dataset you hold. The definition for a random variable is the same idea with probabilities as the weights:

Var(X) = E[(X − μ)²] where μ = E[X]

For the response-length variable, with μ = 260:

x x − 260 (x − 260)² × P(x)
100 −160 25,600 × 0.4 = 10,240
200 −60 3,600 × 0.3 = 1,080
400 +140 19,600 × 0.2 = 3,920
800 +540 291,600 × 0.1 = 29,160
Var(X) = 10,240 + 1,080 + 3,920 + 29,160 = 44,400 tokens²
SD(X) = √44,400 ≈ 210.7 tokens

The 800-token bar carries 29,160 of the 44,400, two thirds of the total, from just 10% of traffic. The squaring from Lesson 2 does what it always does: rare large deviations dominate. A handy equivalent form is Var(X) = E[X²] − (E[X])². Check: E[X²] = 10,000(0.4) + 40,000(0.3) + 160,000(0.2) + 640,000(0.1) = 4,000 + 12,000 + 32,000 + 64,000 = 112,000, and 112,000 − 260² = 112,000 − 67,600 = 44,400. Same result.

Population quantity vs. sample statistic The 44,400 above is a property of the distribution, computed from known probabilities. It is a fixed number, not something you measure with error. In practice you never know the true probabilities. You log, say, 5,000 requests and compute a variance from those, which is a sample statistic: an estimate of the distribution's variance that changes each time you draw a new sample. That is the gap Lesson 5 is about. (When you estimate variance from a sample, the standard recipe divides by n − 1 instead of n. The sample-versus-population difference is why.)

5. Linearity of expectation

You already used this rule above. For any constants a and b, and any random variables X and Y:

E[aX + b] = a·E[X] + b
E[X + Y] = E[X] + E[Y]

The cost example is the first rule: E[2X + 400] = 2(260) + 400 = 920, matching the table calculation. Scaling the variable scales its mean; adding a constant shifts it.

The second rule is the surprising one: it holds even when X and Y are dependent. No independence assumption is needed. Suppose an agent writes a reply, then a follow-up whose length always matches the first (an extreme dependence: knowing X tells you Y exactly). The total is X + X:

E[X + X] = E[X] + E[X] = 260 + 260
= 520 tokens

Direct check: the total is 200, 400, 800, or 1,600 with probabilities 0.4, 0.3, 0.2, 0.1, so E = 80 + 120 + 160 + 160 = 520. It works because expectation is just a weighted sum, and sums of weighted sums rearrange freely. This is why you can budget a multi-step workflow by adding up the expected cost of each step without first untangling how the steps influence each other.

6. How scaling and shifting change variance

Variance does not follow the same rules as the mean:

Var(aX + b) = a² · Var(X)

Two things happen. Adding a constant b slides every value by the same amount, so the spread doesn't change: b drops out. Multiplying by a stretches every distance from the mean by a, and variance squares distances, so it grows by a². Apply it to the cost variable Y = 2X + 400:

Var(Y) = 2² × 44,400 = 4 × 44,400 = 177,600 µ$²
SD(Y) = √177,600 ≈ 421.4 µ$ (= 2 × 210.7)

The standard deviation scales by |a| and ignores b. The fixed prompt cost of 400 µ$ raises the average bill but adds nothing to its unpredictability. Only the part that varies, the output tokens, contributes spread.

7. Sums of independent variables: variances add

Now the sum of different variables. If X and Y are independent (the idea from Lesson 3: knowing one tells you nothing about the other):

Var(X + Y) = Var(X) + Var(Y) (if independent)

Take a three-step agent: retrieve documents, call the LLM, then run a tool. Suppose a team measures each step and finds the following, treating the three as independent:

StepMean (ms)SD (ms)Variance (ms²)
Retrieval12030900
LLM call80020040,000
Tool call80401,600
Mean total = 120 + 800 + 80 = 1,000 ms
Var total = 900 + 40,000 + 1,600 = 42,500 ms²
SD total = √42,500 ≈ 206 ms
Not: 30 + 200 + 40 = 270 ms (standard deviations do not add)

Add the means, add the variances, then take the square root. The total SD of 206 ms is barely above the LLM step's own 200 ms: the LLM call accounts for 40,000 of the 42,500 units of variance. If you wanted to make the whole pipeline more predictable, tuning retrieval from 30 ms SD to 10 ms SD would change the total variance from 42,500 to 41,700. Almost nothing. The variance table tells you where effort pays off.

Pitfall The variance-adds rule needs independence; the mean-adds rule doesn't. Return to the fully dependent two-reply example: the total is X + X = 2X, so Var(2X) = 4 × 44,400 = 177,600. If the two replies had been independent, you'd get 44,400 + 44,400 = 88,800. Dependence doubled the variance. In real pipelines, steps often share a cause (a slow network, a loaded GPU, a long user question that inflates every step), so adding variances can underestimate the true spread of the total. The mean of the total stays correct either way.

8. Building the binomial from Bernoulli variables

These rules let you re-derive the mean and variance from Lesson 11's binomial without any counting. One eval question scored 1 if the model is right and 0 otherwise is a Bernoulli variable C with success probability p:

E[C] = 1(p) + 0(1 − p) = p
E[C²] = 1²(p) + 0²(1 − p) = p (0 and 1 square to themselves)
Var(C) = p − p² = p(1 − p)

Score n independent questions and count the correct ones: the count is C₁ + C₂ + … + Cₙ. Linearity gives the mean by adding n copies of p, and independence lets the variances add:

E[count] = n · p
Var(count) = n · p(1 − p)
n = 50, p = 0.8: mean = 40, variance = 50 × 0.16 = 8, SD = √8 ≈ 2.83

So a model that is truly right 80% of the time scores 40 out of 50 on average, but a typical run lands within about 3 questions of that on either side. The formulas are the ones from Lesson 11; this is where they come from.

9. Averages of many independent runs are less variable

Now divide a sum by n to get an average. The average of n independent copies of a variable with mean μ and variance σ² is (1/n) times the sum, so the rules above give:

E[average] = (1/n) · nμ = μ
Var(average) = (1/n)² · nσ² = σ² / n
SD(average) = σ / √n

The average keeps the same mean but its spread shrinks with the square root of n. Using the LLM step from the pipeline (SD 200 ms), averaging more runs of the same call gives:

Runs averaged (n)SD of the average
1200 / √1 = 200 ms
4200 / 2 = 100 ms
25200 / 5 = 40 ms
100200 / 10 = 20 ms

The same applies to eval scores. A single question has SD √(0.8 × 0.2) = 0.4 around its mean of 0.8. Averaged over 100 independent questions, the accuracy has SD 0.4 / √100 = 0.04. That is the 4 percentage points of noise you should expect between two runs of the same model on two fresh 100-question sets. Over 400 questions it drops to 0.4 / 20 = 0.02. Quadrupling the data only halves the noise, which is why chasing small accuracy differences gets expensive fast.

Key Insight The mean of an average stays put; its variance falls as 1/n. That is the reason repeated measurement works at all: independent errors partly cancel. It is also the shrinking spread behind Lesson 5's sampling error, and it sets up the next question: not just how wide the average's spread is, but what shape it takes as n grows.

10. Why this matters for building AI systems

Why This Matters Almost every number you track in an AI system is a random variable, and every decision about cost, latency, and quality is a statement about its mean and its spread.

Budgeting with expectation, planning with variance

Linearity means cost and token budgets for multi-step workflows are sums of per-step expectations, no matter how the steps interact. But a budget built on the mean alone hides the tail: in the example, 10% of requests cost 2,000 µ$, more than double the 920 µ$ average. Check the CDF as well as the mean.

Latency: find the step that owns the variance

Because independent variances add, you can decompose a pipeline's unpredictability step by step, as in the three-step table. Work on the step with the largest variance, and be suspicious of the independence assumption when steps share infrastructure.

Eval noise: know your error bar before you compare models

An accuracy from n questions has SD around √(p(1 − p) / n). If two models differ by less than a couple of those SDs, you may be looking at noise. Lesson 9 turns this into a proper comparison; here you have the quantity it is built on.

Recap

  • A random variable attaches a number to each outcome (tokens, latency, correct/incorrect). The PMF gives each value's probability; the CDF gives P(X ≤ x).
  • E[X] is the probability-weighted average. In the example it is 260 tokens, a balance point that is not itself a possible value.
  • Var(X) = E[(X − μ)²] is a fixed property of the distribution, not the noisy sample variance you compute from logged data.
  • Linearity: E[aX + b] = aE[X] + b, and E[X + Y] = E[X] + E[Y] even if X and Y are dependent.
  • Variance: Var(aX + b) = a²Var(X); for independent variables, variances add (standard deviations don't). Dependence breaks the variance rule but not the mean rule.
  • The average of n independent runs has the same mean and variance σ²/n, so its SD shrinks as σ/√n.
