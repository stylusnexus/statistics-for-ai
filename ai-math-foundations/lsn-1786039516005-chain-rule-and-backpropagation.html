The Chain Rule & Backpropagation: How Gradients Flow Through a Network

A network is a long chain of small functions. The chain rule turns "how does the loss change if I nudge this one weight?" into a bookkeeping job, and backpropagation is that job done in the cheapest possible order.

M4 gave you the derivative of a single function and the finite-difference check that tests it. M5 gave you partial derivatives and the gradient: one slope per parameter, bundled into a vector. M2 gave you matrices as machines that transform vectors. This lesson joins them. A real model is dozens of layers, each feeding the next, and the slope of the loss with respect to a weight in layer 3 depends on everything downstream of it. The chain rule says how to get that slope. Backpropagation is the chain rule organized so that one sweep through the network yields the slope for every weight. The statistics course, Lesson 8 (The Statistics Behind Training a Model), described gradient descent as a walk downhill. This lesson shows where the direction of that walk comes from.

1. Composite functions and the chain rule

A composite function feeds the output of one function into another: f(g(x)). First compute the inner value u = g(x), then compute y = f(u). A neural network layer is exactly this shape, and a whole network is many of them stacked.

The chain rule says that the slope of the composite is the product of the slopes of the pieces:

dy/dx = (dy/du) × (du/dx)

Read it as a chain of exchange rates. If nudging x by 1 moves u by 3, and nudging u by 1 moves y by 14, then nudging x by 1 moves y by 3 × 14 = 42. Rates multiply.

Example: a polynomial inside a square

Let y = (3x + 1)2 and evaluate at x = 2. Name the inner piece u = 3x + 1.

u = 3x + 1 = 3(2) + 1 = 7
y = u² = 49
du/dx = 3
dy/du = 2u = 2(7) = 14
dy/dx = 14 × 3 = 42

Check with M4's finite difference: nudge x to 2.000001, get y = (7.000003)2 = 49.000042, and (49.000042 − 49) / 0.000001 = 42. The product of local slopes matches the measured slope.

Key Insight Every derivative in the chain is local. The slope of 3x + 1 knows nothing about squaring; the slope of squaring knows nothing about 3x + 1. Each piece only needs its own input and its own output. Backpropagation exploits exactly this: each layer only has to know how to differentiate itself.

2. The computational graph: forward pass and backward pass

Draw a calculation as a computational graph. Each node is one simple operation (multiply, add, sigmoid, subtract and square). Each arrow carries a value from one node to the next. A neural network's loss is one big graph.

  • The forward pass walks the graph from inputs to loss, computing and saving each node's value. This is ordinary inference plus a final loss.
  • The backward pass walks the graph in reverse, from the loss back to the parameters. At each node it takes the gradient arriving from downstream, multiplies by that node's local derivative, and hands the result upstream.

The quantity travelling backward is the slope of the final loss L with respect to the value at that point, written ∂L/∂(value); at the loss node it starts at 1.

3. Worked example: a complete backprop by hand

Build the smallest network that still has a hidden nonlinearity: one input, one hidden unit with a sigmoid, one linear output. Sigmoid is σ(z) = 1 / (1 + e−z); it squashes any number into the range 0 to 1, and its slope is σ′(z) = σ(z)(1 − σ(z)). Suppose a team is fitting a toy score predictor on a single example and every number is fixed up front:

ItemSymbolValue
Inputx1.5
Target (what we want)t1.0
Hidden weight and biasw1, b10.4, 0.1
Output weight and biasw2, b20.9, −0.2
Learning rateη0.5

The model is z = w1x + b1, then h = σ(z), then Ŷ = w2h + b2 (the prediction, written "y-hat"), and the loss is squared error with a half in front so the derivative comes out clean: L = ½(Ŷ − t)2.

Forward pass: compute and save every value

z = w₁·x + b₁ = 0.4(1.5) + 0.1 = 0.7
h = σ(0.7) = 1 / (1 + e^−0.7) = 0.6682
Ŷ = w₂·h + b₂ = 0.9(0.6682) + (−0.2) = 0.4014
L = ½(0.4014 − 1.0)² = ½(0.3583) = 0.1792

The prediction is 0.4014 against a target of 1.0, so the loss is 0.1792. Now the graph, with the forward values on top and the backward gradients underneath:

One gradient-descent step, and a check

All four gradients are negative: raising any parameter would lower the loss. Gradient descent (the statistics course, Lesson 8) subtracts η times the gradient, so each parameter moves up:

w₁ = 0.4 − 0.5(−0.1792) = 0.4896
b₁ = 0.1 − 0.5(−0.1195) = 0.1597
w₂ = 0.9 − 0.5(−0.4000) = 1.1000
b₂ = −0.2 − 0.5(−0.5986) = 0.0993
New forward pass: z = 0.4896(1.5) + 0.1597 = 0.8941, h = 0.7097, Ŷ = 1.1(0.7097) + 0.0993 = 0.8800
L: 0.1792 → 0.0072 (one step cut the loss by about 96%)

They agree to about ten digits when run in code. The whole check, with no libraries:

import math
sig = lambda z: 1 / (1 + math.exp(-z))
def loss(w1, b1, w2, b2, x=1.5, t=1.0):
h = sig(w1 * x + b1)
return 0.5 * (w2 * h + b2 - t) ** 2
p = [0.4, 0.1, 0.9, -0.2]
for i in range(4):
up, dn = p[:], p[:]
up[i] += 1e-6; dn[i] -= 1e-6
print((loss(*up) - loss(*dn)) / 2e-6)
Pitfall The backward pass needs numbers saved from the forward pass (h = 0.6682 and x = 1.5 both appeared as local derivatives), so a framework keeps every layer's intermediate values in memory. That is why training needs far more memory than running a model.

4. When one variable feeds two places: sum over paths

In the tiny network every variable fed exactly one next node. Real networks branch: one value goes to two places, and both influence the loss. The multivariable chain rule says to add up the contributions along each path.

Take a variable x that feeds two nodes, u = x + 1 and v = x2, which are then multiplied: f = u × v. At x = 3:

u = 4, v = 9, f = 36
Path through u: ∂f/∂u × du/dx = v × 1 = 9
Path through v: ∂f/∂v × dv/dx = u × 2x = 4 × 6 = 24
df/dx = 9 + 24 = 33

Check: f = (x + 1)x2 = x3 + x2, so df/dx = 3x2 + 2x = 27 + 6 = 33. A finite difference at step 0.000001 also returns 33.00001.

This is common: a residual connection (section 7) sends a layer's input down two routes, and a shared embedding table receives a gradient from every position where a token appears. Whenever two gradients arrive at the same node in a backward pass, they are added.

5. The matrix form: Jacobians and why backward is cheap

The examples above have one number per node. A real layer takes a vector in and gives a vector out. The M5 gradient generalizes to the Jacobian: a matrix whose entry in row i, column j is the partial derivative of output i with respect to input j. For a layer with 1,000 inputs and 1,000 outputs, the Jacobian is a 1,000 × 1,000 matrix. (For a linear layer a = Wz from M2, the Jacobian is simply W itself.)

The chain rule for a stack of layers then reads: the Jacobian of the whole network is the product of the layer Jacobians. Only the order of multiplication is a choice, and the order decides the cost:

  • Forward mode multiplies from the input side. Getting all the gradients takes one sweep per parameter: a million sweeps for a million parameters.
  • Reverse mode (backprop) multiplies from the loss side. It starts with a single row vector, the gradient of one scalar loss, and multiplies it by one Jacobian at a time. Each step is a vector times a matrix. One sweep produces the gradient for every parameter.

The difference is large. A 1,000-entry vector times a 1,000 × 1,000 matrix costs about 1,000,000 multiply-adds. Two 1,000 × 1,000 matrices cost about 1,000,000,000. Backprop keeps the left factor a vector, so it never pays the second price.

Key Insight Reverse mode is cheap because training has the shape many inputs, one scalar output: millions or billions of parameters, one loss number. A single backward pass costs roughly a small multiple of the forward pass, no matter how many parameters there are. That one fact is what made training large networks practical. The price, as the pitfall above noted, is memory for the saved forward values.

6. Vanishing and exploding gradients

The backward pass multiplies one factor per layer. A long product of numbers is dangerous: if the factors are mostly below 1 the product shrinks toward zero, and if they are mostly above 1 it blows up.

Sigmoid is the classic case. Its slope σ′(z) = σ(z)(1 − σ(z)) peaks at z = 0, where σ = 0.5 and the slope is 0.5 × 0.5 = 0.25. It is never larger. In the tiny network the slope was 0.2217, already close to that ceiling, and it shrinks quickly when z is large in either direction. Now stack layers. If each layer's weight is 1 and every sigmoid sits at its best case, each layer multiplies the gradient by at most 0.25:

Sigmoid layersBest-case gradient factorValue
50.2550.00098

With 10 layers, the gradient reaching the first layer is under one millionth of the gradient at the output. The early layers receive almost no signal, so they barely learn. That is the vanishing gradient problem, and it is the best case. Sigmoid slopes are at most 0.25, so this is the best case for a chain of sigmoids; large weights can offset it, which is the exploding side of the same product.

The mirror image is the exploding gradient. If each layer's factor is 1.5 instead, the product grows:

1.510 = 57.7
1.530 = 191,751
1.550 ≈ 637,621,500

A gradient that large produces a wild update, and the loss can jump to infinity or NaN. The usual remedy is gradient clipping: if the gradient's length exceeds a limit, rescale it to the limit before updating.

7. Why ReLU and residual connections help

ReLU

The ReLU activation, max(0, z), has slope exactly 1 for any positive input and 0 for a negative one. For active units the factor per layer is therefore 1 rather than at most 0.25, so a product of many such factors does not shrink just from the activation. A negative input has slope 0 and passes no gradient, so units can get stuck "dead"; and the weights still multiply in. ReLU lowers the risk but does not remove it.

Residual connections

A residual connection computes y = x + F(x), adding the input back onto the output. Differentiating gives dy/dx = 1 + dF/dx. That "+1" is the sum-over-paths rule from section 4 at work: the gradient has a direct route that skips F entirely, so even if dF/dx is tiny, the total factor stays near 1 instead of near 0. This is one reason very deep networks became trainable. It is a helpful property, not a guarantee; a deep network still needs sensible initialization and learning rates.

8. Automatic differentiation: the framework does it, you still need to know what flows

Nobody derives these equations by hand for a real model. Deep-learning frameworks track the computation as the forward pass runs, then execute reverse-mode automatic differentiation to produce every gradient. Each primitive operation ships with its own local derivative; the framework just chains them. A call like loss.backward() is the backward pass from section 3, at scale.

Knowing the mechanism still pays. A NaN gradient means look for a node with a huge local derivative. Slow early layers mean vanishing factors. Out-of-memory in training but not inference means saved forward values. A non-differentiable operation, such as rounding or a hard argmax, stops the gradient there.

9. Why this matters for building AI systems

Why This Matters Every weight in every neural network you will use was set by a gradient that backpropagation computed. The mechanism is short enough to hold in your head, and it explains many failures that otherwise look mysterious.

Debugging training

If loss does not move, print the gradient size per layer. Near-zero gradients in early layers and healthy ones late point to vanishing factors; spikes point to exploding ones. Exactly zero for a group of parameters often means something is detached from the graph.

Cost and memory

One backward pass costs a small multiple of a forward pass and needs the activations stored. That is why recomputing activations instead of storing them exists, and why fine-tuning few parameters, as LoRA does, cuts memory: frozen parameters need no stored gradient.

Leads into M7

Derivatives answer "how fast does this change?" M7 covers integrals: adding up a quantity that varies continuously. That is how a probability density becomes a probability, how an expected value over a continuous distribution is computed, and why normalizing constants appear in probabilistic models. It connects the calculus you now have back to the statistics course.

Recap

  • The chain rule: for y = f(u) and u = g(x), dy/dx = (dy/du)(du/dx). Local slopes multiply. Example: y = (3x + 1)2 at x = 2 has slope 14 × 3 = 42.
  • A computational graph splits a model into simple nodes. The forward pass computes and saves values; the backward pass multiplies gradients by each node's local derivative, from the loss back to the parameters.
  • Worked network: gradients −0.1792, −0.1195, −0.4000, −0.5986 for w1, b1, w2, b2; one step at η = 0.5 took the loss from 0.1792 to 0.0072, and finite differences confirmed every gradient.
  • When a variable feeds several nodes, the gradients along each path add (the example gave 9 + 24 = 33).
  • Backprop multiplies Jacobians from the loss side, vector times matrix, so one sweep gives all parameter gradients. The cost is memory for the saved forward values.
  • Sigmoid's slope is at most 0.25, so 10 layers can shrink a gradient to about 10−6; factors above 1 explode instead. ReLU and residual connections keep the factors nearer to 1, but do not guarantee stable training.
  • Automatic differentiation does the bookkeeping, but you still debug by knowing what flows and where it can stop.
